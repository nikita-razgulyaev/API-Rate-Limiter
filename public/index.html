Три rate-limiting алгоритма на атомарных Lua-скриптах Redis, живой дашборд и три способа подключения к вашему продукту: Express-middleware, reverse proxy и HTTP API для любого языка. Работает без Redis из коробки, а на своём сервере или VPS разворачивается за пару минут.

01

Один клиент кладёт весь API

Без лимитов один скрипт или баг на стороне клиента способен исчерпать квоту к внешним сервисам и уронить прод для всех остальных.

02

Работает без обвязки

Без Redis сервер сам переключается в in-memory режим — ничего не нужно разворачивать, чтобы посмотреть демо. Добавил Redis — то же приложение стало распределённым.

03

Прозрачность для клиента

Заголовки X-RateLimit-* в каждом ответе — интеграторы видят остаток квоты и время сброса, не гадая вслепую.

Fixed Window

Простой счётчик на временное окно. Минимум памяти и вычислений.

  • + Самый дешёвый в эксплуатации
  • + Предсказуемое поведение
  • − Всплеск x2 на границе окон
Лучше для: внутренние сервисы, низкий риск
◔

Sliding Window

Скользящий журнал таймстампов — лимит применяется плавно, без скачков на границе.

  • + Нет burst-эффекта Fixed Window
  • + Честное распределение во времени
  • − Дороже по памяти (Redis sorted set)
Лучше для: публичные API с высокими требованиями к точности
⛁

Token Bucket

Бакет пополняется токенами непрерывно — допускает короткие всплески, держит средний темп.

  • + Разрешает легитимные всплески
  • + Алгоритм Stripe, GitHub, AWS
  • − Чуть сложнее объяснить клиенту
Лучше для: API с неравномерной нагрузкой

Reverse proxy

Ставите перед своим API — код продукта не меняется. Правила по методу и пути, ключ по IP или заголовку (например, X-API-Key).

MODE=proxy
UPSTREAM_URL=http://127.0.0.1:8080
REDIS_URL=redis://localhost:6379
RULES_FILE=./rateshield.rules.json
node server.js
{ }

Express-middleware

Для Node-приложений: подключается одной строкой, использует тот же Redis и алгоритмы.

const { createStore, rateLimit } =
  require('rateshield');
const store = createStore({
  url: process.env.REDIS_URL });
app.use('/api', rateLimit(store, {
  algorithm: 'sliding',
  limit: 100, windowSec: 60 }));
⌁

HTTP API решений

Для любого языка (Python, PHP, Go, Java): ваш бэкенд спрашивает «можно ли?» и сам решает, что ответить клиенту.

curl -X POST $HOST/_rateshield/v1/check \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key":"user:42","rule":"login"}'
# {"allowed":true,"remaining":4,...}
  • 🐳 Docker: docker compose up -d поднимает сервис и Redis с сохранением данных.
  • 🔐 Безопасность по умолчанию: API проверки и статистика существуют только при заданном ADMIN_TOKEN; IP клиента берётся из X-Forwarded-For лишь от доверенных прокси.
  • ♻️ Правила без рестарта: изменили JSON — kill -HUP, и новые лимиты применены.
  • 📖 Пошаговая инструкция для VPS (Docker + HTTPS через Caddy, либо systemd): docs/SELF-HOSTING.md в репозитории.
